# 복권 분석·추천 (자동 갱신 버전)

매일/추첨 직후 GitHub 가 데이터를 대신 받아 두고, 휴대폰 앱은 열 때마다 그 데이터를 읽습니다.
비용은 0원이고, 설치는 한 번만 하면 됩니다. (PC 로 하는 것을 권장)

## 설치 (약 10분)

### 1. GitHub 가입 · 저장소 만들기
1. https://github.com 에서 무료 가입
2. 오른쪽 위 **+ → New repository**
3. 이름: `lotto-helper` (아무거나 가능) / **Public** 선택 → **Create repository**
   - Public 이어야 무료로 웹페이지(Pages)를 쓸 수 있습니다. 올라가는 것은 당첨번호(공개 정보)와 코드뿐이고, 개인정보는 없습니다.

### 2. 파일 올리기
1. 받은 ZIP 의 압축을 풉니다.
2. 저장소 화면에서 **uploading an existing file** (또는 Add file → Upload files) 를 누르고, 압축 푼 **폴더 안의 내용 전체**를 끌어다 놓습니다.
3. 아래쪽 **Commit changes** 클릭
4. `.github` 폴더가 올라가지 않았다면(숨김 폴더라 빠질 수 있음), 직접 만듭니다.
   - **Add file → Create new file** → 이름 칸에 `.github/workflows/update.yml` 입력 (슬래시를 치면 폴더가 만들어집니다) → 압축 푼 곳의 같은 파일 내용을 복사해 붙여넣기 → Commit
   - `.github/workflows/discover.yml` 도 같은 방법으로 만듭니다.

### 3. 웹페이지(Pages) 켜기
1. **Settings → Pages**
2. Source: **Deploy from a branch** / Branch: **main**, 폴더 **/ (root)** → **Save**
3. 1~2분 뒤 같은 화면에 주소가 나옵니다: `https://내아이디.github.io/lotto-helper/`

### 4. 첫 데이터 받기
1. **Actions** 탭 → (처음이면 "enable workflows" 버튼을 누릅니다)
2. 왼쪽 **데이터 갱신** → **Run workflow** → 1분쯤 뒤 초록 ✔ 확인
3. 저장소의 `data/lottery.json` 을 열어 `"latest": 12xx` 가 최신 회차인지 확인

### 5. 휴대폰에서 쓰기
위 주소를 휴대폰 브라우저로 열고 **메뉴 → 홈 화면에 추가**.

## 자동으로 도는 시간 (한국 시간)
| 언제 | 무엇 |
|---|---|
| 토 21:30, 일 06:30 | 로또 |
| 목 20:30 | 연금복권 (연결 후) |
| 매일 07:00 | 스피또 (연결 후) |

GitHub 예약 실행은 몇 분~수십 분 늦을 수 있습니다. 앱 상태 창에 "예상 최신 회차"가 함께 표시되니 뒤처졌는지 바로 알 수 있습니다.

## 연금복권·스피또 연결하기
아직 데이터 주소를 확인하지 못해 `scripts/sources/pension.mjs`, `speetto.mjs` 가 비어 있습니다.
1. **Actions → 주소 탐색 (한 번만 실행) → Run workflow**
2. 끝나면 실행 기록을 열어 **로그 전체를 복사**해서 Claude 에게 붙여넣어 주세요. 그 주소로 두 파일을 채웁니다.

## 문제가 생기면
- **빨간 ✗** 가 뜨면 GitHub 가 메일로 알려 줍니다. 실행 기록을 열어 오류 문구를 확인하세요.
  기존 데이터는 지워지지 않고 그대로 유지됩니다.
- 로또는 공식 조회가 막히면 비공식 JSON(smok95/lotto)으로 자동 대체됩니다.
- 저장소에 아무 활동이 없으면 GitHub 가 60일 뒤 예약 실행을 멈출 수 있습니다. (데이터가 바뀔 때마다 자동 커밋이 생기므로 보통은 해당 없음) 멈추면 Actions 탭에서 다시 켜세요.
- 공식 사이트 개편 등으로 형식이 바뀌면 검증에서 걸러져 갱신이 멈춥니다. 그때는 알려 주세요.

## 참고
- 과거 번호를 집계하는 참고·재미용 도구입니다. 추첨은 매 회 독립이라 어떤 조합도 당첨 확률은 같습니다.
- 접속은 하루 1~2회 수준으로 가볍게 유지하도록 만들었습니다.
- 개발자용 시험: `node --test scripts/test/update.test.mjs`
